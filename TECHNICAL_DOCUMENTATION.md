# OpenScantron technical documentation

## Runtime and layout

Kotlin and Compose Material 3 use Navigation Compose and a Hilt view model. A Hilt singleton repository owns the Room database and the private vault. Room Flow drives the UI. WorkManager schedules local reconciliation. DataStore holds theme and PDF resolution preferences. CameraX preview, analysis and JPEG capture run through Android camera providers. Gallery and camera originals both enter `Repository.capture`; image processing and disk publication use I/O dispatchers.

The immutable `SheetLayout` JSON has a schema number, template UUID, exam UUID, paper, item count, ordered labels, and ID-column count. Geometry code for schema 1 lives in `domain/Layout.kt`. The origin is the upper left, X increases right and Y increases down. Multiply X by page width and Y by page height for PDF Canvas coordinates or canonical pixel units. Circular radii and square extents are defined relative to width on both axes to preserve shape. A4 uses 595 × 842 PDF points, Letter uses 612 × 792. Schema 1 fits 1–100 items over up to four columns of at most 25 rows, 2–6 distinct labels of one or two ASCII alphanumeric characters, and 1–8 left-to-right decimal ID digits. Longer reserved status labels are excluded by the label grammar. The generated PDF labels the template with its UUID prefix.

The registration-square centers are at (.055,.045), (.945,.045), (.945,.955), and (.055,.955). A square's edge measures .025 × page width. Three smaller asymmetric cues determine rotation. The QR centered at (.795,.161) covers .18 × page width. Its payload is `OS:schema:exam_uuid:template_uuid:optional_roster_uuid`. The last part is an opaque ID. Names, student numbers and section information are kept out of the QR. New layout definitions get new identities and old layouts remain available through key versions.

## Recognition

The app preserves the original image bytes and normalizes EXIF for display and analysis. OpenCV builds a local adaptive threshold image and finds solid square candidates. It filters quadrilaterals by scale, convexity, shape and coverage, tests four cyclic orientations against asymmetric cues, and estimates a projective warp to a 1120-pixel-wide canonical image. The warped sheet must match a sample of independently positioned printed outlines. A readable conflicting QR rejects the scan. An unreadable QR produces a warning while the selected layout still has to pass registration. Corner visibility and geometry failures leave the original and separate archive available. Camera analysis uses a lower-resolution alignment check gated by lighting and contrast. Auto-capture requires four aligned observations and clears its repeat latch after three unusable observations.

Bubbles use an interior radius about .71 of their printed radius. Local paper is the 83rd percentile in an exterior annulus. Each interior sample contributes `clamp((paper - value - 22) / (.63 × paper), 0, 1)`, averaged per bubble. Default thresholds are .12 for possible ink, .34 for a strong mark, and .14 for winner margin. A confident single also requires only one possible choice. The measured margin is the difference between the top two evidence values. Evidence and margin are unitless contrast measurements. A reassuring margin does not bypass layout checks. Each column in the student number uses the same classification rules.

The detector is tuned against synthetic fixtures in this repository. Tests cover clean registration, 90° rotation, perspective, low contrast/shadow combined with mild blur, conflict QR, and missing markers. Physical sheets, high curvature, different printer inks and faint or erased marks require held-out evaluation. See the test report for measured scope.

## Model and state

- **Examination**, **AnswerSheetTemplate**, **AnswerKeyVersion** hold the exam's metadata, stable geometry, and frozen answers/scoring. Changing an active key does not recalculate old grades. Explicit regrade preserves the original scan key and appends grade history using the new grading key. The layout must match.
- **Student** has a UUID and a unique text number. **ScanBatch** pins exam, template, and key. **Submission** has a UUID, scan order, source path/hash, assigned student, rotation, recognition state, grade, inclusion, and effective-attempt flag. The batch/order pair is unique.
- **QuestionRecognition** has a compound submission/question key. The machine classification, candidates, evidence and margin remain immutable after successful registration. **AnswerCorrection** is append-only. The latest decision per item determines the effective answer, saved separately as a submission projection. **GradeHistory** records confirmed results and explicit regrades. Relationships used for batch creation, assignment, and regrading are checked in repository transactions. Staged restore validates the associated identifier graph before commit.
- **AnswerSheetArchive** manages one individual PDF per capture. **BatchDocument** stores its ordered page-to-submission list. **DatasetArchive** tracks the last successful revision/generation, row count, combined size, hashes, and attempt/error timestamps. Artifacts reference relative vault paths.
- Inclusion is `INCLUDED`, `DECISION_REQUIRED`, `SUPERSEDED`, or `DISCARDED`. Identity match and source SHA-256 inform duplicate review. Replace supersedes one predecessor, preferring the effective attempt for that student. Retain creates a different attempt. For statistics the repository prefers an already effective confirmed attempt, then another confirmed attempt, then an included candidate. The audit CSV exposes that flag.
- Capture publishes the original and inserts the queued submission and PDF row before recognition. Recognition and PDF states move independently from queued to ready or error. Successful recognition publishes evidence, effective grade, and the exam revision in one database transaction. Explicit confirmation requires an assigned student, included attempt and zero mark-review items. The dataset includes recognized provisional submissions.
- The supplied Room baseline is schema 1. The 1→2 migration adds nullable publication-attempt timestamps to individual archive and dataset tables. The 2→3 migration materializes effective answers from immutable observations and existing corrections. All exported JSON schemas are under `app/schemas`. The builder does not fall back to destructive migration.

## Scoring and statistics

For each item, multiply its points by its nonnegative weight (default 1). Correct, wrong, blank and invalid values are separately configured. Multiple marks default to review. The invalid policy uses invalid points, and partial credit gives `correct_points × fraction` if the pinned correct answer was among the marked candidates. Other multiple marks use invalid points. A teacher can resolve review to one configured label, blank or invalid.

`maximum` is the sum of each weight times full-credit points. The optional zero floor applies after summing all contributions and deductions. `percentage = 100 × score / maximum` for positive maximum. With zero maximum, percentage and percentage-based passing status are unset. Points-based passing is still available. Unresolved items contribute zero provisionally and suppress final pass/fail. Threshold comparisons use full precision. UI rounds to two decimal places.

Class statistics use one effective confirmed submission per assigned student, with optional section filtering. Mean and median use earned points with the pinned scoring scheme for each record. The active key's maximum is displayed separately. Pass rate divides by final effective records with a defined decision. For an item, the denominator is final effective attempts whose form included that question. The difficulty index is the fraction correct. Count the most frequent wrong answer label as the distractor, breaking equal frequencies by label. Provisional records and non-effective retained attempts remain in answer exports.

## CSV dictionary

Wide columns follow the requested order. Stable UUIDs identify submissions, exams and batches. `student_id` is the roster number as text and may be empty for an unassigned sheet. The title, subject, date, name and section reflect current stored metadata. `scanned_at` is an ISO-8601 UTC timestamp. `answer_key_version` is the integer grading revision within the exam.

Q001 through Qnnn contain the effective answer or `BLANK`, `MULTIPLE`, `AMBIGUOUS`, `INVALID`, or `PENDING_REVIEW`. The latter token is reserved. Review flags are separate in the audit. In a consolidated file or an exam with older layouts, trailing empty cells mean the question did not apply. An actual unanswered question is always `BLANK`. Counts describe observed/effective categories. Provisional rows leave `score`, `percentage`, and `passing_status` empty. `max_score` remains available. A final row may have empty percentage/pass data under a zero maximum. `grading_status` is `FINAL` or `PROVISIONAL`.

The audit has one row per applicable question and includes IDs, template and key, machine and effective answers, selected alternatives, fill evidence, margin, classification, review status, latest correction presence/time, and effective-attempt flag. Candidate lists use `|`; evidence order is the template label order. Room retains all corrections. CSV is UTF-8 with CRLF rows and standard doubled quotes. Decimals use a period. Import IDs as strings in downstream tools.

## Publication, backup and recovery

Image PDFs aspect-fit the complete oriented image into 16-point margins. The archive uses an incremental PDF writer with one temporary JPEG at a time and validates page count with Android PdfRenderer. Batch order defaults to capture order or can use student ID. JPEG resolution changes apply to subsequently generated individual archives. The unmodified original remains separate. Validating an existing individual PDF checks its recorded SHA-256 and opens it.

The repository serializes mutations and publication in one process. File writes use a unique temporary sibling, fsync and atomic replacement. CSV publication writes both files into an exam-revision directory and swaps Room references after both succeed. An error keeps the last published files. An older revision cannot mark a newer revision synced. Queued work replays using stable IDs after a restart. Crash leftovers in the private vault can be removed after their Room references are reconciled. A failed derived file can be retried in its archive or dataset view. Corrupt files are rejected on access. Free storage and retry when writes fail. Original deletion requires a verified individual PDF and completed recognition. It removes the bytes needed for recognition retry and new batch PDFs. Archive metadata and audit history remain.

A version-1 backup ZIP starts with `manifest.json`. It contains version, UTC creation time, original-image inclusion, record tables and a relative-path SHA-256 map. `files/<relative-path>` entries hold the recorded PDFs, CSVs, rectified views and optional original images. Restore to an empty installation stages data, rejects unknown or traversing paths, validates references and file hashes, opens PDFs and parses CSVs, then commits records in one transaction. A failed restore preserves existing data. ZIPs are ordinary unencrypted exports and should be saved to controlled storage. Platform cloud backup and device transfer are excluded. Source images, student data and keys stay on-device except for documents the teacher chooses to export.
